# hosts-and-import Specification

## Purpose

Specifies how users organise, find, edit and move hosts in Termax: the Hosts & Vault home (grid/list/tree, groups, tags, smart filters, fuzzy search, environment colours, multi-select, broadcast groups), the three-tier host editor side sheet with App→Vault→Group→Host→Session inheritance, autosave, version history, undo delete, connection test, quick connect, and the import/export engine (~/.ssh/config, known_hosts, PuTTY, Termius CSV, ssh_config, TOML, termax:// and ssh:// deep links).

Source: BRD-02 “Hosts, host editor & import/export” v1.0 (draft) (2026-10-30). Modules: UI-02, UI-03, CO-11. Generated by `tools/openspec_from_brd.py`; edit through OpenSpec changes.

## Business rules

- **BR-02-01**: Resolution order: Session > Host > Group (nearest ancestor first) > Vault > App; a profile attached to a layer sits right after that layer's own overrides. No layer stores a value unless it is explicitly overridden (no PuTTY-style full snapshots).
- **BR-02-02**: Secrets (passwords, passphrases, proxy passwords) never live in host_settings, host_versions, logs or export files; they are stored only as encrypted vault records referenced by id.
- **BR-02-03**: Environment is a dedicated, inheritable attribute (prod/staging/dev/custom), always shown with a text label. A host with env = prod or the tag “prod” counts as production: broadcast, bulk delete and every agent operate action require confirmation.
- **BR-02-04**: Deletion is soft: hosts/groups go to Trash for 30 days; permanent deletion happens only when the user explicitly chooses it in Trash; deleting a host never deletes referenced identities or known hosts.
- **BR-02-05**: Imports are non-destructive: nothing is written until Commit; source files and registry are read-only and never modified (except the ssh_config Include line the user consents to in FR-CO11-011, backed up first).
- **BR-02-06**: Duplicate key within a vault: (normalised address, port, username); label clashes are resolved with a “ (2)” suffix.
- **BR-02-07**: Deep links from outside Termax never run commands and always require a confirmation showing user, host, port and host-key status; unsupported parameters are ignored and reported.
- **BR-02-08**: Third-party product names appear only as plain-text import-source labels (“PuTTY saved sessions”, “Termius CSV”), with no logos; pending legal confirmation in Q-02-03.

## User journeys

### J-02-01 Migrating from PuTTY on Windows
1. First run detects 120 PuTTY sessions and 85 host keys in the registry.
2. The wizard previews: 112 New, 5 Duplicate, 3 with plaintext ProxyPassword (warned).
3. The user picks Merge for the 5 duplicates and commits; ProxyPassword moves into the vault.
4. Hosts are grouped into suggested groups by name prefix; host keys go to Known Hosts with SHA256 fingerprints.
5. The report lists unmapped PuTTY keys; a Revert import action stays available for 30 days.

### J-02-02 An SRE filters prod hosts and creates a broadcast group
1. Import ~/.ssh/config with `Include config.d/*`; 240 hosts land in the vault.
2. Type `tag:prod AND os:linux` in the filter bar; 18 hosts appear with 2 chips.
3. Save as the smart filter “prod-linux”; Mod+A selects all 18.
4. Choose “Create broadcast group”; a confirmation lists the prod hosts; confirm.
5. A new tab opens the first 16 panes (default limit) and reports the 2 remaining hosts, with broadcast on and labelled.

### J-02-03 Editing a host with inheritance and restoring a version
1. Set font 14 and keepalive 10 s on group “Network gear”.

## Data entities

- **vaults**: id (UUIDv7), name, kind(personal|team), created_at, updated_at, lamport, deleted_at — Vault defaults live in host_settings with scope=vault. Team vaults arrive in P2 (BRD-11).
- **groups**: id, vault_id, parent_id, name, position, env, profile_id, created_at, updated_at, deleted_at, import_job_id — Group tree; group overrides live in host_settings scope=group.
- **hosts**: id, vault_id, group_id, label, address, port, protocol(ssh|telnet|serial|raw|local), username, identity_id, env, notes, os_hint, profile_id, last_connected_at, connect_count, version, created_at, updated_at, deleted_at, import_job_id, source_ref — Holds no secrets; source_ref records the import source file:line or registry key.
- **host_settings**: id, scope(app|vault|group|host|profile), scope_id, overrides_json (sparse key→value), secret_refs_json (key→vault secret id), schema_version, updated_at, device_id — Sparse JSON overrides for every inheritance layer; the Session layer lives in memory only.
- **tags**: id, vault_id, name, colour_token, created_at — Tag names are unique within a vault.
- **host_tags**: host_id, tag_id (composite PK) — Many-to-many host ↔ tag link.
- **import_jobs**: id, source(ssh_config|known_hosts|putty_registry|putty_dir|termius_csv|toml), source_path, started_at, committed_at, status(previewed|committed|cancelled|reverted|failed), counts_json, report_json, reverted_at — Reports are redacted; used for the 30-day Revert import.
- **host_versions**: id, host_id, version, snapshot_json (no secrets), changed_fields, reason(edit|restore|import|duplicate|revert), created_at, device_id — Keeps ≥50 versions or 90 days.
- **smart_filters**: id, vault_id, name, query, position, is_broadcast_group, layout_json — Queries share the parser with the palette, CLI and MCP.
- **profiles**: id, vault_id, name, description, created_at, updated_at — Profile values live in host_settings scope=profile.

## Interfaces

- **IF-02-01 HostService (termax-core)** (Rust API): list/query(filter AST), get, upsert, soft_delete, restore, duplicate; emits change events for the UI, sync (P2) and the managed Include.
- **IF-02-02 SettingsResolver (termax-vault)** (Rust API): resolve(host_id, session_overrides) → EffectiveConfig with per-key provenance (layer, scope id, profile).
- **IF-02-03 FilterQuery (termax-core)** (Rust API): parse(query) → AST or an error with position; shared by Hosts, the palette, the CLI and MCP list_hosts.
- **IF-02-04 Importer trait (termax-interop)** (Rust API): detect() → SourceSummary; scan(source) → ImportPlan; apply(plan, resolutions) → ImportJob; revert(job_id).
- **IF-02-05 Exporter (termax-interop)** (Rust API): to_ssh_config(selection, mode), to_toml(selection), sync_managed_include(vaults).
- **IF-02-06 ConnectionProbe (termax-ssh / termax-proto)** (Rust API): probe(target) → stream of step results (DNS, TCP, banner, KEX, host key, auth methods); never opens a shell channel.
- **IF-02-07 DeepLinkRouter (termax-platform)** (URL scheme): termax://host, termax://connect, ssh://, telnet:// → confirmation sheet; shares the router with BRD-01's termax://settings.
- **IF-02-08 tmx import | tmx host ls --filter --json | tmx export ssh-config** (CLI (PL-04)): The CLI uses the same import/export engine and filter parser through the local control endpoint or a headless runtime.
- **IF-02-09 MCP list_hosts / host metadata (termax-mcp)** (MCP tool/resource (AG-02)): Returns host ids, labels, environments, tags and groups for a filter; never returns secrets or proxy credentials.
