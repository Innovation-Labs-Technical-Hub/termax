# mobile-apps Specification

## Purpose

Define the Termax app for iOS/iPadOS and Android built with Flutter 3.47 + flutter_rust_bridge 2.13, sharing termax-core (SSH, terminal parser, vault, policy, sync) with desktop. Beta in P2 (months 9-12), GA in P3. Focus: smooth 60 fps terminal painted from Rust Frame/Damage, a 44 pt extra-keys bar, fast session keep/resume (≤2 s after resume), biometric unlock, and approving external-agent requests from the phone.

Source: BRD-12 “Mobile apps (Flutter)” v1.0 (draft) (2026-10-30). Modules: MO-01, MO-02. Generated by `tools/openspec_from_brd.py`; edit through OpenSpec changes.

#### Scenario: FR-MO02-007 specified behaviour
- **GIVEN** the system implements FR-MO02-007

## Business rules

- **BR-12-01**: The mobile app is free and local-first (ARCH-BRIEF §1); cross-device sync needs Pro. ARCH-BRIEF §11 lists 'mobile' under Pro — to be settled (Q-12-01).
- **BR-12-02**: All protocol, cryptography, terminal parsing and policy logic lives in termax-core (Rust); Dart only does UI and platform integration.
- **BR-12-03**: No downloaded code execution and no local shell on iOS; no WASM plugins on mobile v1.
- **BR-12-04**: AI-proposed commands run only after the user taps 'Run in terminal'; external-agent approvals need biometric confirmation; pushes carry no command, host or agent names.
- **BR-12-05**: Every swipe action has a visible alternative (long-press menu or overflow button); no gesture-only features.
- **BR-12-06**: Auth prompts (password, passphrase, OTP) appear in a native sheet, never inside the terminal grid (D9).
- **BR-12-07**: Crash reports and telemetry are off by default and enabled only with consent and a payload preview (D8).
- **BR-12-08**: No mosh (GPL-3.0) code is bundled; roaming uses Eternal Terminal (Apache-2.0), or clean-room mosh only after legal approval (D5).

## User journeys

### J-12-01 Handle an incident from the phone
1. The user opens the app, Face ID unlocks the vault, types 'api' in search and taps host 'api-prod-3' (red PROD label with text).
2. The terminal opens full screen; the extra-keys bar (Ctrl, Tab, arrows) is used to run 'journalctl -u api -f' and Ctrl+C.
3. They switch to Slack for 40 s; Termax saves a screen snapshot before suspension.
4. On return: a 'Reconnecting…' overlay and the new session is ready within ≤2 s, auto-attaching to the configured tmux.

### J-12-02 Approve an external-agent request away from the desk
1. Claude Code on the desktop asks Termax's MCP server to run 'systemctl restart nginx' on a staging-tagged host; policy returns 'ask'.
2. The desktop sends an E2EE approval request to the user's devices; the phone gets a push 'Termax: approval requested' (no command text).
3. Opening it shows the approval sheet with agent, host, command, risk level and time left; the user picks Allow once and confirms with Face ID.
4. The decision is signed with the device key and returned; the desktop verifies the signature and runs the command; the audit records the phone as approver.

### J-12-03 Upload a file from the phone to a server
1. In Files/Photos the user taps Share → Termax.
2. Termax opens SFTP and asks for the destination host (defaulting to the most recent) and folder.
3. The queue shows progress, speed and ETA; if the app is backgrounded beyond the OS allowance, the transfer pauses and resumes on reopen.

### J-12-04 First run with a Pro account
1. The welcome screen offers: Use locally (no account) or Sign in to sync.
2. They choose Sign in, enter email + password and scan the Emergency Kit QR with the camera (or approve from the desktop).
3. The app offers Face ID; the vault downloads its snapshot and works offline right away.

## Data entities

- **(shared) vault schema**: hosts, identities, keys, snippets, known_hosts, settings — same SQLite schema as desktop (BRD-06) — No mobile-specific schema; shared migrations.
- **extra_keys_layouts**: id, name, rows(json: key|snippet_ref|modifier), is_default, updated_at — Synced as a vault record.
- **session_snapshots**: session_id, host_id, frame_blob, cursor, scrollback_tail, saved_at — Saved on backgrounding; encrypted with the vault key; deleted when the session closes.
- **host_mobile_prefs**: host_id, font_size, keepalive_interval, keepalive_count, tmux_autoattach, et_enabled — Host tier in the inheritance chain.
- **push_registrations**: device_id, platform(apns|fcm), token_enc, created_at, revoked_at — Token encrypted; pushes carry no content.
- **approval_requests**: id, origin_device_id, request_ciphertext, expires_at, decision, decision_sig, decided_by_device, decided_at — Content encrypted to device keys; relayed via oxsync.

## Interfaces

- **IF-12-01 termax-ffi TerminalApi (open, frames() -> Stream<FrameDelta>, input(bytes), resize(cols, rows, px))** (flutter_rust_bridge 2.13): Streams Frame/Damage from termax-term; input and resize back to Rust.
- **IF-12-02 termax-ffi VaultApi / SyncApi / SftpApi / AgentApi** (flutter_rust_bridge 2.13): Thin wrappers over termax-core APIs shared with desktop.
- **IF-12-03 Platform keystore plugin (Keychain + Secure Enclave / Android Keystore + BiometricPrompt)** (Flutter platform channel (Swift/Kotlin)): Wraps/unwraps the vault key with a hardware key after biometric authentication.
- **IF-12-04 Push via oxsync → APNs / FCM** (HTTPS (server-side)): Sends content-free notifications only, to wake the app.
- **IF-12-05 Approval relay (E2EE message to user devices)** (oxsync WebSocket/REST): Encrypted + signed approval requests and decisions between desktop and phone.
- **IF-12-06 iOS Share Extension / Android ACTION_SEND + Storage Access Framework** (OS integration): File intake for SFTP and config/key import.
- **IF-12-07 Deep links ssh://, termax://, universal/app links** (OS URL handling): Opens prefilled Quick connect; unknown hosts always confirmed.
