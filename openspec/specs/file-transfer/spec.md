# file-transfer Specification

## Purpose

Define the business requirements for Termax's dual-pane file browser and SFTP/SCP transfer engine: browse, transfer and manage local and remote files inside the workspace, over the SSH connection that is already open, with a transparent queue (speed, ETA, resume), safe overwrites and throughput of at least 80 % of OpenSSH sftp at 100 ms RTT.

Source: BRD-05 “File transfer (SFTP/SCP)” v1.0 (draft) (2026-10-30). Modules: UI-05, CO-06. Generated by `tools/openspec_from_brd.py`; edit through OpenSpec changes.

### Requirement: FR-CO06-002 Adaptive pipeline from limits@openssh.com
The system SHALL provide: Adaptive pipeline from limits@openssh.com.

Source: BRD-05 FR-CO06-002 · Module: CO-06 · Priority: Must · Phase: P1

#### Scenario: FR-CO06-002 specified behaviour
- **GIVEN** the system implements FR-CO06-002
- **THEN** Request size = min(max-read-length / max-write-length from limits@openssh.com, 256 KiB); 32 KiB without limits. #### Scenario: FR-CO06-002 acceptance 1
- **GIVEN** an OpenSSH server advertising max-read-length 261120
- **WHEN** downloading a 1 GiB file
- **THEN** each READ asks for 256 KiB and traces show ≥64 requests in flight at steady state

#### Scenario: FR-CO06-002 acceptance 2
- **GIVEN** a server without limits@
- **WHEN** uploading
- **THEN** each WRITE is 32 KiB and there are no SSH_FX_FAILURE errors from oversized requests

### Requirement: FR-CO06-005 Resume of partial files and transfer journal
The system SHALL provide: Resume of partial files and transfer journal.

Source: BRD-05 FR-CO06-005 · Module: CO-06 · Priority: Must · Phase: P1  
VI: Resume file dở và transfer journal

#### Scenario: FR-CO06-005 specified behaviour
- **GIVEN** the system implements FR-CO06-005
- **THEN** Each job writes a journal (an encrypted record in the vault DB): source, destination, source size+mtime, confirmed offset, .oxpart path. Downloads resume from the local .oxpart size; uploads resume after stating the remote .oxpart and comparing a hash of its last 1 MiB (read back) with local data. #### Scenario: FR-CO06-005 acceptance 1
- **GIVEN** a 4 GB download interrupted at 62 %
- **WHEN** the connection returns
- **THEN** the transfer continues from the confirmed offset and the final file's SHA-256 matches the source

#### Scenario: FR-CO06-005 acceptance 2
- **GIVEN** the source mtime changed since the job started
- **WHEN** resuming
- **THEN** the engine restarts from 0 and shows the reason ‘Source changed’

### Requirement: FR-CO06-006 Safe replace: temp + posix-rename/fsync with fallback

## Business rules

- **BR-05-01**: Never overwrite a destination file silently. The default conflict policy is Ask per item; ‘Apply to the remaining N items’ is scoped to the current job only.
- **BR-05-02**: Uploads always write to a temporary .<name>.oxpart-<id> in the same directory and are renamed afterwards. Use posix-rename@openssh.com when the server advertises it and the engine supports it; otherwise use the documented ‘backup-rename’ fallback (BR-05-03).
- **BR-05-03**: Fallback without posix-rename: destination absent → SSH_FXP_RENAME; destination present and overwrite allowed → rename the destination to .<name>.oxbak-<id>, rename the temp file to the destination, delete the backup; if step 2 fails, restore the backup. This non-atomic window is recorded in the connection log as ‘non-atomic replace’ and documented for users.
- **BR-05-04**: Resume only when source size and mtime match the values recorded in the transfer journal at start; otherwise restart and state why.
- **BR-05-05**: Recursive operations do not follow directory symlinks unless the user explicitly enables it; symlink loops are detected and skipped with a warning.
- **BR-05-06**: File content is never logged. Paths are redacted in every output that leaves the machine or reaches a model: diagnostics bundles, AI context, MCP results; for the local connection log, path redaction is a per-host option.
- **BR-05-07**: External agents (MCP) may only list/stat by default; reading content needs per-call approval; write, delete and chmod exist only in operate mode (P2) via the AG-03 policy engine.
- **BR-05-08**: SFTP opens on the host's existing SSH connection (a new channel) and does not ask for authentication again (H6).
- **BR-05-09**: Deleting remote files always needs confirmation stating item count and total size, because SFTP has no trash; deleting local files moves them to the OS trash.

## User journeys

### J-05-01 Upload a build artifact by drag and drop from the terminal context
1. The user is in a terminal pane on host staging-api, directory /srv/app/releases (the shell emits OSC 7).
2. They press Mod+E: SFTP opens in dual pane, the remote pane already at /srv/app/releases and the local pane at Downloads.
3. They drag app-2.4.1.tar.gz (1.2 GB) from Finder/Explorer into the remote pane.
4. The file already exists → the conflict sheet shows size and mtime of both sides; they choose Overwrite.
5. The queue shows progress, speed and ETA; the file is written to a temporary name and then renamed atomically; a toast confirms completion and the connection log records a one-line summary (paths redacted on export).

### J-05-02 Resume a 4 GB download after a network drop
1. A 4 GB db-dump.sql.gz download is at 62 % when Wi-Fi drops.
2. The item moves to Paused (network) and keeps its .oxpart file; the session auto-reconnects with backoff (BRD-04).
3. After reconnecting, the engine checks that source size+mtime are unchanged and continues from the recorded offset.
4. On completion the .oxpart file is renamed to the real name; total time and attempt count show in the item details.

### J-05-03 Edit nginx.conf in a local editor with upload on save
1. The user selects /etc/nginx/nginx.conf and presses Mod+Enter (Edit locally) → it opens in VS Code from a private temp folder (0700).
2. On every save Termax uploads via temp + rename; a ‘Syncing nginx.conf’ chip shows on the pane.
3. A colleague edits the file on the server; on the next save Termax detects the changed remote mtime and asks: Overwrite remote / Download remote to compare / Save as copy.
4. Closing the editor or clicking Stop editing deletes the temp file.

### J-05-04 Keyboard-only work in a 100k-entry directory
1. They open /var/spool/mail-archive (100,000 files); the first rows appear as soon as the first READDIR batch arrives and the rest streams in.
2. They type ‘inv-2026-10’ to filter with type-ahead, press Shift+Down to select 40 files and F5 to copy them to the local pane.
3. They select a folder, press Alt+Enter to open the permissions sheet, change 0755 → 0750 recursively with a preview of the affected item count, and confirm with Enter.

## Data entities

- **transfer_jobs**: id, session_id, host_id, direction(up|down|remote), state, conflict_policy, parallelism, created_at, updated_at, payload_ct (encrypted: src, dst, filters) — Paths live in the encrypted payload because they may be sensitive.
- **transfer_items**: id, job_id, state, size, bytes_confirmed, src_size, src_mtime, partial_name, attempts, error_code, speed_ewma, payload_ct (encrypted: src_path, dst_path) — Journal that drives resume and queue restore after restart.
- **sftp_capabilities**: host_id, protocol_version, extensions(json), max_read, max_write, max_packet, max_handles, observed_at — Per-host server capability cache; refreshed on every channel open.
- **sftp_bookmarks**: id, host_id, label, payload_ct (encrypted: path), created_at — Per-host bookmarks, synced with the vault (P2).
- **edit_sessions**: id, host_id, state, remote_mtime, remote_size, editor, payload_ct (encrypted: remote_path, local_temp_path), created_at — Tracks Edit-locally files for conflict detection and temp cleanup.
